# 自己管理KPI

週次ログのMarkdownから公開用のKPIデータを生成し、統計ページとして公開します。
測定と公開の方針は `C:\product\static\definitions.md` が正で、このリポジトリはそれを実装したものです。

## 起動

```bash
npm start
```

`http://localhost:3458` で開きます。`PORT` 環境変数で変更できます。

## 週次の手順

```bash
node scripts/build-kpi.js
```

1. 週次ログアプリで「Markdownを生成・保存」（期間は土曜〜金曜、出力内容は「すべて」）
2. 出力された `weekly-log-開始日_終了日-all.md` を `logs/` にコピー
3. 上のコマンドを実行
4. コンソールの警告を確認する（下記）
5. `data/` の3ファイルを公開先へ反映

引数で入出力先を変えられます。

```bash
node scripts/build-kpi.js --logs=別のフォルダ --out=別のフォルダ
```

## 設計上の原則

**追記しない。毎回ゼロから全期間を再生成する。**

分類の定義は実際にドリフトしています（「写経」が11週目は基礎学習、12週目は回復・生活）。
差分を追記する方式だと、定義を1つ変えた瞬間に過去の週が古い定義のまま取り残され、
時系列グラフが嘘になります。全再生成なら、定義を変えてビルドし直すだけで過去も追従します。

**公開しない項目はコードで落とす。**
運用ルールではなくホワイトリストで塞ぐことで、事故で漏れる経路を構造的に消します。

**列は位置ではなく見出し名で読む。**
ログの列構成は週ごとに変わっており（移動列の追加、開始/終了/推定の追加）、位置固定では必ず壊れます。

## 出力

| ファイル | 中身 | 1年後の目安 |
| --- | --- | --- |
| `data/current.json` | 直近の完了週（日次・見積もり明細・学習ノート付き） | 約3KB（固定） |
| `data/recent-4w.json` | 過去4週（欠測週を含む） | 約12KB（固定） |
| `data/all-weekly.json` | 全期間の週次集計のみ（1行/週） | 約10KB |

ビューごとに事前集計を分けています。1ファイルに全部入れて追記すると、
全期間グラフを見るだけで使わない日次明細を大量に転送することになります。

「今週」ではなく**直近の完了週**を出します。週は土曜始まりなので、
土日にアクセスされると1〜2日分しか埋まっていないグラフになるためです。

## ビルドを止める条件

以下に該当するとビルドは失敗し、ファイルを書き換えません。

- **恒等式の不一致** — `作業時間合計 == 作業ブロックの分 + ヒアリング（実施+振り返り）`。
  ログに記載された集計値と再計算値が違えば止めます。
- **期間が7日でない** — `exports/` の単日エクスポートが紛れ込んだ場合に検出します。
- **週の開始日の重複**
- **非公開項目の混入** — ログ側で捨てたはずの値（ひとこと・業種・自己評価・署名など）が
  出力に現れていないかを照合します。固定の禁止語リストではなく入力から動的に集めるので、
  新しい症状名や業種名も取りこぼしません。

## 過去週の変化の検知

全再ビルド方式では、分類マッピングを1つ変えるだけで半年前の数値も動きます。
それは意図した挙動ですが、バグでも同じことが起きます。

ビルドは前回の出力と突き合わせ、**先週分の追加ではなく過去週の数値が変わっていたら**知らせます。

```
過去週の数値が 2件 変わりました。意図した再解釈かバグかを確認してから公開してください:
  2026-07-18  categories.基礎学習: 555 → 235
  2026-07-18  categories.回復・生活: 0 → 320
```

止めはしません（再正規化は正当な変更のため）。公開前に必ず目を通してください。

## 指標について

- **主指標は平均誤差（分）**、従が「±10分以内に収まった割合」です。
  一致率は閾値の取り方で数字が大きく動くため、連続量である平均誤差を主にしています。
- **見積もり実施率を必ず併記します。** これがないと、見積もりやすい作業だけを見積もることで
  平均誤差をいくらでも小さくできてしまいます。
- **最大の外れ1件を除いた値も併記します。** ログに変更理由の列がなく「予定変更」を自動判別できないため、
  意図を推測せず機械的に最大の外れを除いた値を出します。両方出すことで恣意的な除外を防ぎます。
- **`estimate.basis`** は `実測`（打刻ベース／新regime）か `自己申告`（旧regime）です。
  旧regimeには打刻が存在せず、除外すると過去の実績がすべて消えるため、
  捨てずに基準を明示して残しています。グラフでは境界の前後を描き分けてください。

## 欠測週

記録できなかった週は `{ weekStart, weekEnd, recorded: false }` として残します。
`0` で埋めると平均を引き下げてグラフが谷になり、記録しなかった週と作業0分の週の区別がつきません。

## 公開ページ

`server.js` は Express + EJS で、DBを持たず `data/` のJSONだけを読みます。

**書き込み機能がありません。フォームが1つも無いのでCSRFの攻撃面がゼロです。** これが最大のセキュリティ設計です。

### 表示の作り

数値と表はEJSでサーバー側レンダリングし、グラフはその上にChart.jsで重ねています。
**JavaScriptが動かなくても、グラフが潰れても、数値はすべて表で読めます**（生HTMLに10表・54行、約16KB）。
採用者はスマートフォンで見ますし、スクリーンショットを他の人に回します。

タブで3つの期間を切り替えますが、グラフの種類は増やさず同じ3枠のデータを差し替えます。
ただし全期間だけは表現を変えています。散布図のままだと52週×十数件で数百点の団子になって読めないため、
週ごとの平均誤差の推移（折れ線）にしています。時間配分も、絶対値だと総作業時間の増減と
比率の変化が混ざるため、全期間では100%積み上げにしています。

グラフは表示中のタブの分だけ生成します。非表示のcanvasは幅が0になり描画が崩れるためです。

### CSP

Helmetの既定よりも締めています。すべて自ホストなので外部オリジンを許可する必要がなく、
フォームを持たないので `form-action` も要りません。

```
default-src 'self'; script-src 'self'; style-src 'self'; form-action 'none'; frame-ancestors 'none'; object-src 'none'
```

この構成では次の2つが動きません。**CSPを緩めるのではなく、構成で解決しています。**

- CDNからChart.jsを読む → `public/vendor/chart.umd.js` に自ホスト
- `<script>` タグ内にグラフ設定を直接書く → `public/js/charts.js` に分離

`style-src` に `'unsafe-inline'` は不要です。CSPが止めるのはHTML中のstyle属性と `<style>` 要素であって、
Chart.jsがJSからcanvasに当てるスタイルは対象外です（動作確認済み）。

### キャッシュ

静的ファイルは `max-age=0` + ETag による再検証にしています。
`max-age` を長く取ると、更新後も古いJS/CSSがその時間だけ配信され続けるためです。
週1回更新するページなので、常に最新を配って変更がなければ304を返す方が適しています。

## 求職活動の扱い（2026-08-01 決定）

**そのまま公開します。** 面接・ハローワーク・書類作成も「営業」分類に含めて出しています。
実際に時間を使った活動を分ける理由がなく、都合の良い項目だけを残すと残りの数字の信用も落ちるためです。
